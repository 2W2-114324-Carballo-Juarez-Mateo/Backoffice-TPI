
[G06-HU01] — Modificación y versionado de parámetros globales (PAR-01..24)

> **Épica:** EP-01 · Parámetros Globales
> **En simple:** el administrador cambia las reglas de la plataforma desde una pantalla; cada cambio queda anotado y vale de ahora en adelante. - Épica 01 · Parámetros Globales

Descripción (Como / Quiero / Para)
Como: ADMIN
Quiero: cambiar el valor de un parámetro global (PAR-01..24) desde la consola, indicando el valor nuevo y el motivo
Para: ajustar las reglas de la plataforma (puntos, monedas, penalizaciones) sin depender de un programador, conservando el registro de qué valores estuvieron vigentes y en qué momento

Notas / Observaciones
Reglas de negocio:
- Solo el rol ADMIN modifica parámetros globales; el PROFESOR solo los consulta.
- Cada cambio crea una nueva versión y se conserva el historial.
- El cambio rige desde su vigencia en adelante; los resultados históricos no se recalculan.
- La operación acepta una clave de idempotencia para evitar duplicados por reintentos de red.
- El valor debe respetar el rango permitido de cada parámetro.
Validaciones:
- El parámetro debe existir (PAR-01..24).
- El valor debe estar dentro del rango del parámetro.
- La fecha de vigencia no puede ser anterior a hoy.
- El motivo debe tener una longitud mínima.
Datos obligatorios: key del parámetro, valor nuevo, motivo (la fecha de vigencia es opcional; si no se indica, aplica de inmediato).
Performance: la operación responde en menos de 100 ms (P95).
Seguridad: solo ADMIN modifica; PROFESOR lee los valores vigentes sin ver quién los cambió ni el historial.
Accesibilidad: la pantalla de edición es usable por teclado y cumple WCAG AA.
Otros: el cambio se propaga por Kafka a los consumidores (se detalla en US-02).

Criterios de Aceptación (CA)
CA1: Al guardar un cambio válido, el sistema crea la nueva versión, registra el historial y responde 200 OK con el valor y la versión resultantes.
CA2: Si se reenvía la misma petición con la misma clave de idempotencia, el sistema responde el resultado anterior sin crear otra versión.
CA3: Si un PROFESOR intenta modificar, el sistema responde 403 Forbidden y no cambia nada.
CA4: Si el valor está fuera de rango o la fecha es retroactiva, el sistema responde 400/422 con un mensaje claro.

BDD (mínimo 3 escenarios)
Característica: Modificación de parámetros globales

Escenario 1: Modificación válida
Dado: un usuario con rol ADMIN
Y: el parámetro PAR-19 tiene versión 3
Cuando: envía una solicitud para cambiar el valor a "25" con un motivo
Entonces: el sistema guarda la versión 4, registra el historial y responde 200 OK

Escenario 2: Reintento duplicado
Dado: que el cambio de PAR-01 ya se procesó con la clave "abc-123"
Cuando: el cliente reenvía la misma solicitud por un corte de red
Entonces: el sistema responde el resultado anterior sin generar una nueva versión

Escenario 3: Acceso denegado
Dado: un usuario con rol PROFESOR
Cuando: intenta modificar un parámetro
Entonces: el sistema responde 403 Forbidden y el valor no cambia
