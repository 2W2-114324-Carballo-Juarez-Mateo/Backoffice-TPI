[G06-HU05] — Sustitución y conmutación de modelos de IA

> **Épica:** EP-03 · Modelos LLM y Golden Set
> **En simple:** cuando un modelo ya está aprobado, el administrador puede activarlo y cambiar el que está en uso; el sistema avisa a los servicios que lo usan.

Descripción (Como / Quiero / Para)
Como: ADMIN
Quiero: activar un modelo aprobado como el que se usa y conmutar entre modelos homologados
Para: cambiar de proveedor según costo o calidad, sin interrumpir las evaluaciones en curso y avisando a los servicios que lo consumen

Notas / Observaciones
Reglas de negocio:
- Solo un modelo puede estar activo a la vez para cada función.
- Solo se puede activar un modelo que ya pasó la revisión de calidad ("aprobado").
- Al conmutar, el modelo anterior pasa a reserva y se publica el aviso con el anterior y el nuevo.
- Si se intenta activar un modelo no aprobado, se rechaza.
Validaciones:
- El modelo debe estar en estado "aprobado".
- No se puede activar un modelo inexistente o retirado.
Datos obligatorios: modelo a activar.
Performance: la conmutación se aplica sin interrumpir evaluaciones en curso.
Seguridad: solo ADMIN opera.
Accesibilidad: la pantalla de activación es usable por teclado y cumple WCAG AA.
Otros: el aviso de cambio se publica en Kafka (`ModelProviderChanged`).

Criterios de Aceptación (CA)
CA1: Al activar un modelo aprobado, queda activo, el anterior pasa a reserva y se publica el aviso con ambos modelos.
CA2: Si se intenta activar un modelo no aprobado, responde 409 y no cambia nada.
CA3: El evento `ModelProviderChanged` llega con el modelo anterior y el nuevo.
Extras (opcional): —

BDD (mínimo 3 escenarios)
Característica: Sustitución y conmutación de modelos de IA

Escenario 1: Conmutación exitosa
Dado: que "gpt-4o-mini" y "claude-3-5-sonnet" están aprobados
Cuando: el ADMIN activa "claude-3-5-sonnet"
Entonces: queda activo, el anterior pasa a reserva y se publica el aviso de cambio

Escenario 2: Rechazo de un modelo sin aprobar
Dado: un modelo que todavía no pasó la revisión de calidad
Cuando: el ADMIN intenta activarlo
Entonces: responde 409 y no lo activa

Escenario 3: Publicación del aviso
Dado: una conmutación exitosa entre dos modelos
Cuando: se activa el nuevo
Entonces: los servicios que lo usan (T04/T07) reciben el evento con el modelo anterior y el nuevo
